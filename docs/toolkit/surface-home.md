# Homepage toolkit: task-first refinement

Mode: Persuade, transitioning to Operate when the visitor opens a tool. This is a focused refinement of the existing Deep End identity, not a whole-site redesign.

## User and job
A first-time visitor does not know the Champ product names. They need to choose between evaluating an existing list, finding a new buying signal, tracking a link and editing a PDF. They need to know whether the destination is on this site, a separate product, source code or an internal project. Build-log activity dates do not answer those questions.

## Product truth
Harbinger is the buying-signal product. Confirmed against `/Users/deep/repos/ChampHarbinger/README.md` and the reachable marketing deployment https://champharbinger.vercel.app. No authenticated workflow or shared wallet integration was exercised. Link wording must be Explore, not a claim of verified execution.

Lead Scorer is list evaluation: CSV/XLSX, enrichment, email verification, ICP/custom judgments. The current staged upgrade uses Treg and Jev. It is not a promise to source new prospects or write outreach automatically.

Deep Scanner is the internal Celsus sensitivity scanner. Confirmed against the GTM Intelligence Series build brief and the real `scan-sensitivity.py` source. Regex-based text scanning, BLOCK/REVIEW/PASS categories, frontmatter overrides. A public GitHub lookup returned 404, which means no public release could be verified, not proof that no private repo exists. Do not advertise it as an available web app or call it an enrichment tool. No live folders were scanned during this work.

## Reach of change
Update canonical toolkit data, homepage launcher, toolkit gallery defaults and descriptions, generated data/HTML, browser tests and documentation. No change to Harbinger's own code, authentication, billing or deployment. Keep existing site shell, fonts and identity tokens. Remove the homepage's unrelated in-use/trying/watching sidebar from the product-choice flow; retain that content in the toolkit's build-stack disclosure.

## 21st.dev references actually inspected
- https://21st.dev/@meschacirung/components/features/features-with-info : feature-led hierarchy and a readable product preview. Adapt the information hierarchy to the existing React/CSS stack. Do not import its Next Image, Tailwind or icon-card grid.
- https://21st.dev/@ravikatiyar162/components/file-upload-card : file selection, selected-file feedback and explicit remove/cancel affordances. Do not copy the demo's fake progress timer or mock files.
- https://21st.dev/blog/react-file-upload-components : real keyboard file input alongside drop, upfront size/type limits, validation on both sides and actionable errors.

The reference pages, displayed code and preview images were reviewed. No paid registry component was installed and no 21st API credential was requested. The implementation is original project-native markup/CSS informed by these references, not an asserted 21st SDK integration.

## Composition
Two primary task features: evaluate a list (Lead Scorer) and investigate buying signals (Harbinger). Short task heading, product name, input/output explanation and explicit destination action. Two compact secondary rows: smart links and browser PDF tools. Deep Scanner receives a clearly labelled explanation in a native disclosure, not a dead launch button. The gallery opens on hosted products; source projects and previews are deliberate opt-in filters.
