# Backend database contract

> SUPERSEDED before implementation by `toolkit-platform.md`. User identity must be a verified Clerk subject, not an auth.users UUID. Usage reservations belong to a shared cross-tool credit wallet. This draft is retained only as accounting threat-model input; do not implement these ls_-scoped account tables.

All RPCs only executable by service_role. Edge backend authenticates via auth.getUser REST first, passes authenticated UUID. Postgres SQL functions fixed search_path public, pg_temp. RLS all tables, no direct authenticated/anon grants. Do NOT grant any cross-user select through public policies.

Tables prefixed `ls_` to leave legacy records alone.

- ls_settings: singleton id=1, daily_cap_micro bigint default 0, halted bool default false. Lock this row first in every reserve and admin update to serialize global spend decisions. Environment caps also default 0. Admin bootstrap manual SQL on ls_accounts.is_admin only, never email allowlist or metadata.
- ls_accounts: id uuid references auth.users, email text, is_admin bool false, daily_cap_micro bigint 0, daily_row_cap integer 0, disabled bool false.
- ls_runs: id uuid (request_id), user_id uuid, request_hash text, list_name text, created_at timestamptz default now, day date UTC from database clock, row_count int, status text running/completed/review, reserve_micro bigint, spent_micro bigint 0, held_micro bigint (initial reserve), results jsonb [], error text. Entire batch ceiling reserved atomically before provider call. Pending/in-flight runs held indefinitely until explicit reconciled completion, never automatic time release. Outstanding holds from ALL days count against current day and user caps. Spent costs count on original reserved run day, but completed late-night settlement must still be safe: keep global/user holds on all-days and count spend by ledger settled_at UTC day. Simpler safe policy: hold age-crossing runs as review; never release across midnight without admin reconciliation.
- ls_operations: id uuid, run_id uuid references ls_runs, ordinal int unique per run, provider text, endpoint text, reserved_micro bigint, cost_micro bigint nullable, status text pending/settled/unknown, response jsonb optional. Logged BEFORE dispatch. No operation can be started twice. Unknown costs remain held at full reservation. Confirmed zero is zero, missing charge is NULL. Need timestamps for actual spend recognition.

RPC exact shapes:

`ls_touch(p_user uuid,p_email text)` ensure account exists or update email only, returns account JSON.
`ls_usage(p_user uuid)` returns {usage:{day,spent_micro,held_micro,rows,daily_cap_micro,daily_row_cap,disabled},runs:[last 30 summary objects id,list_name,status,created_at,row_count,spent_micro,held_micro]}. Rows used today includes current day runs + prior-day RUNNING/REVIEW rows. Holds all days, spending on reservation day with midnight policy above.
`ls_reserve(p_user uuid,p_id uuid,p_hash text,p_list_name text,p_rows int,p_reserve bigint)` returns run JSON. Global row lock, account checks, limits, reserve integer bounded, unique ID retry returns existing same user AND same hash, otherwise error. JSON includes id,status,results,spent_micro,held_micro,error. Validate 1<=rows<=5. Cap violation raises meaningful error text 'budget exceeded' or 'row limit exceeded'. Per-request ceiling <=250000 micro to bound a batch independently. Doesn't trust client reservation; service backend computes p_reserve. Check global halted. If any pending/review run has prior day, fail closed for that user's new runs until reconciliation; global outstanding hold already counts.
`ls_start_operation(p_user uuid,p_run uuid,p_id uuid,p_ordinal int,p_provider text,p_endpoint text,p_reserve bigint)` ensure ownership/status running and total operation allocations <= run reserve, insert pending op. Return op. Replay errors, never re-dispatch pending operation.
`ls_finish_operation(p_user uuid,p_id uuid,p_cost bigint default NULL,p_response jsonb default NULL)` update pending op to settled or unknown, store bounded response. Idempotent same completion; reject conflicting completion. Cost > reserved should still record actual truth and HALT global processing (settings.halted=true). Don't hide overage. Returns operation. No cap release until finish_run.
`ls_finish_run(p_user uuid,p_id uuid,p_results jsonb,p_error text default NULL)` recompute spent=sum settled actual; holds=sum reserved for unknown/pending ops. Release never-used reserve only when no unaccounted providers. If run's original UTC day != current UTC day, retain ALL original reserve as hold and mark review (conservative). Status review if unknown/pending/error, else completed. Return full run + ledger (summary operations provider,endpoint,status,cost_micro,reserved_micro). Idempotent existing finalized return only, don't overwrite results. Reserve fault before provider dispatch => finish with no ops, holds 0; error recorded review. All settled charges below/at cap ledger complete.
`ls_run_detail(p_user uuid,p_id uuid)` owner only full run + ledger. Admin is not automatically entitled to uploaded contacts.
`ls_admin_usage(p_user uuid)` verify is_admin, return {day,global:{daily_cap_micro,spent_micro,held_micro,halted},users:[id,email,is_admin,daily_cap_micro,daily_row_cap,disabled,spent_micro,held_micro,rows]}.
`ls_admin_update(p_user uuid,p_target uuid default NULL,p_cap bigint default NULL,p_rows int default NULL,p_disabled bool default NULL,p_global bigint default NULL)` verify admin, lock settings before account. Partial request must validate integers nonnegative <=1000000000 micro and rows<=100000; user branch requires all 3 fields cap/rows/disabled. Can't mutate is_admin. Global only updates cap, never clears halted flag. Return admin usage readback.

For initial version, unresolved charge reconciliation is explicit operator SQL after provider invoice review, not a user-facing arbitrary refund button. Document this gap honestly. Public beta defaults caps 0, admin must verify vendor pricing before grant. Tests must execute REAL PostgreSQL migration against isolated disposable database only, with mock auth.users and standard roles locally if absent. Never write existing application DBs. Cover concurrent reservations and row caps, self escalation, IDOR, same-ID replay, conflicting retry, zero allowance, unknown holds, overage circuit breaker. No external credentials needed. No commits or deploys.
